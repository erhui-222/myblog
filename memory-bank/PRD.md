## 1. 产品概述

### 1.1 项目名称

**MyBlog —— 个人博客系统**

产品由两个端构成：

- **用户端（前台）**：面向访客的公开站点，用于浏览博主的文章与个人信息。
- **博主管理后台（后台）**：面向博主本人的私密管理界面，用于登录与文章内容管理。

**技术形态（已定）**：前后台共用一个数据库，前台采用服务端渲染（SSR）输出 HTML。发布即生效，404 可返回真实 HTTP 状态码。

### 1.2 项目目标

| 目标 | 说明 | 衡量方式 |
| --- | --- | --- |
| 建立稳定的个人内容阵地 | 提供一个不依赖第三方平台的独立博客站点，长期沉淀原创文章 | 站点可正常访问，文章可持续发布 |
| 提供轻量顺畅的阅读体验 | 访客用最少的操作路径找到并读完一篇文章 | 从首页到正文页 ≤ 2 次点击；正文页正文首屏可见 |
| 让博主自己能管理内容 | 博主无需懂技术、无需改代码即可完成文章的创建、修改、下线与删除 | 全流程在后台 3 步内完成；全流程无报错 |
| 让内容效果可被观测 | 通过阅读量数据判断哪些文章真正被阅读，为后续选题提供依据 | 每篇文章有累计阅读量；仪表盘可看到总量与单篇分布 |

### 1.3 核心价值

1. **对访客**：打开即读，无需注册、无弹窗干扰，快速定位感兴趣的文章并沉浸阅读。
2. **对博主**：内容主权归自己，写作与维护成本低，一个后台即可掌控全部文章，且能看到文章是否有人读。
3. **对产品本身**：结构简洁、边界清晰，MVP 以最小功能集跑通「写 → 发 → 读」的完整闭环，后续可低成本扩展评论、标签、订阅等能力。

### 1.4 产品范围（MVP 边界）

- **本期包含**：首页文章浏览、文章详情阅读、关于我、博主登录、后台仪表盘（文章统计 + 阅读量）、文章管理（列表 / 新增 / 编辑 / 删除 / 查询 / 预览）、文章回收站、阅读量统计。
- **本期不含**：访客注册登录、评论与回复、点赞收藏、标签与分类体系、全文检索（仅标题与摘要模糊匹配）、RSS 订阅、多博主 / 多租户、草稿协作、图片素材库（仅支持单张封面上传）、数据导出、第三方登录、关于我页面的后台可视化编辑、文章定时发布。
- 以上不包含项作为二期候选，需另行评审。

## 2. 目标用户

### 2.1 用户角色划分

| 角色 | 描述 | 使用端 | 核心诉求 | 使用频次 |
| --- | --- | --- | --- | --- |
| 访客（读者） | 通过分享链接、搜索引擎或社交平台进入站点的普通浏览者，无需注册 | 用户端 | 快速了解博主是谁、读到有价值的内容、顺畅地连续阅读 | 偶发、被动进入为主 |
| 潜在关注者 | 对博主内容产生兴趣、可能长期回访或主动联系的人 | 用户端 | 判断博主是否值得关注、获取联系方式 | 低频、逐步沉淀 |
| 博主（管理员） | 站点的唯一内容所有者与运营者 | 管理后台 | 发布与管理文章、掌握内容概况与阅读效果、随时修正错误 | 高频，写作与维护时使用 |

### 2.2 用户画像

**画像 A：访客 · 小林（技术从业者）**

- 场景：在社交平台看到一篇被转发的文章链接，用手机点开。
- 目标：30 秒内判断这篇内容是否有用，有价值则读完并可能继续看其他文章。
- 痛点：移动端排版拥挤、加载慢、强制登录、正文被广告打断。
- 关键诉求：移动端可读性好、正文排版舒适、能一键返回文章列表继续浏览。

**画像 B：访客 · 阿哲（非技术背景，通过朋友介绍）**

- 场景：朋友推荐「这个人的博客不错」，从首页进入。
- 目标：先了解博主是谁、在做什么，再决定看哪篇文章。
- 痛点：不知道从哪开始看，缺少引导与自我介绍。
- 关键诉求：首页有清晰的文章入口，有「关于我」页面了解背景与联系方式。

**画像 C：博主 · 本站所有者**

- 场景：周末写完一篇文章，需要发布；或发现旧文有笔误需要修正。
- 目标：不碰代码，用最短路径完成发布 / 修改 / 下线。
- 痛点：手动改文件、部署、容易出错；找不到自己以前写过哪些文章；发出去才发现排版错乱；误删文章找不回来。
- 关键诉求：登录简单、编辑界面直观、发布前能看到真实排版、文章列表可筛选可搜索、误删可从回收站恢复、能一眼看到文章总量与阅读情况。

### 2.3 核心使用场景

| 编号 | 场景 | 角色 | 主流程 |
| --- | --- | --- | --- |
| S1 | 浏览首页并挑选文章 | 访客 | 进入首页 → 浏览文章卡片列表 → 点击感兴趣的文章 |
| S2 | 阅读单篇文章 | 访客 | 打开正文页 → 阅读 → 返回列表或看其他推荐 |
| S3 | 了解博主 | 访客 | 点击导航「关于我」→ 阅读简介与联系方式 |
| S4 | 登录后台 | 博主 | 访问后台地址 → 输入账号密码 → 进入仪表盘 |
| S5 | 发布新文章 | 博主 | 仪表盘 → 文章管理 → 新增 → 填写标题/内容 → 预览确认 → 保存并发布 |
| S6 | 维护已有文章 | 博主 | 文章管理 → 搜索/筛选定位 → 编辑或删除 |
| S7 | 查看内容概况 | 博主 | 登录后进入仪表盘 → 查看文章总数、发布状态分布、阅读量、最近更新 |
| S8 | 恢复误删文章 | 博主 | 文章管理 → 回收站 → 找到文章 → 恢复 |
| S9 | 发布前确认排版 | 博主 | 编辑页 → 点击预览 → 新标签打开预览页核对 → 返回发布 |

### 3.1 F1 用户端 · 首页

#### 3.1.1 功能描述

首页是站点的入口，承担「自我介绍 + 内容索引」两个职责：让访客第一时间知道这是谁的博客、在写什么，并能快速找到想读的文章。

**功能点清单**

| 编号 | 功能点 | 描述 | 优先级 |
| --- | --- | --- | --- |
| F1-1 | 站点导航 | 展示站点名称 / Logo 与导航项（首页、关于我），当前页高亮；移动端折叠为汉堡菜单 | P0 |
| F1-2 | 博主简介区（Hero） | 展示博主头像、昵称、一句话简介与社交 / 联系入口 | P0 |
| F1-3 | 文章列表 | 按发布时间倒序展示已发布文章卡片，每页固定条数 | P0 |
| F1-4 | 文章卡片 | 单卡展示标题、摘要、封面图（可选）、发布时间、阅读时长 | P0 |
| F1-5 | 分页 | 列表超过单页容量时分页；URL 携带页码，支持刷新与分享 | P0 |
| F1-6 | 空状态 | 无已发布文章时展示友好空状态文案，不出现空白页 | P1 |
| F1-7 | 页脚 | 版权信息、备案信息（如需）、站点建立年份 | P1 |

> 注：文章标签体系本期不做，用户端不展示任何标签元素；阅读量本期也不在用户端展示，仅在后台可见。

**业务规则**

1. 首页仅展示 `status = published` 且未被删除（`deleted_at IS NULL`）的文章。
2. 文章排序规则：`published_at` 倒序；同时间以 `id` 倒序兜底。
3. 摘要优先取文章「自定义摘要」；未填写则由系统自动生成：取正文纯文本前 120 字，在第 120 字之前最近的一个句末标点（。！？.!?）处截断，无标点则硬截断。Markdown 标记不计入字数。
4. 分页默认每页 10 条，页码越界时重定向到最后一页并提示。
5. 首页为 SSR 渲染，文章数据变更后无需重建即可生效。

**页面组件**

| 组件名 | 类型 | 说明 | 关键属性 / 状态 |
| --- | --- | --- | --- |
| `SiteHeader` | 布局组件 | 顶部导航容器，滚动时吸顶 | `siteName`、`navItems`、`currentPath`、`isMobileMenuOpen` |
| `NavMenu` | 导航组件 | 导航项列表，当前页高亮 | `items[]`、`activeKey` |
| `MobileMenu` | 抽屉组件 | 移动端汉堡菜单，点击遮罩关闭 | `open`、`onClose` |
| `HeroSection` | 展示组件 | 头像 + 昵称 + 一句话简介 + 社交图标 | `avatarUrl`、`name`、`tagline`、`socialLinks[]` |
| `ArticleList` | 列表容器 | 承载文章卡片网格 / 纵向列表与分页 | `articles[]`、`loading`、`error` |
| `ArticleCard` | 卡片组件 | 单篇文章入口卡片，整卡可点击 | `id`、`slug`、`title`、`excerpt`、`coverUrl`、`publishedAt`、`readingTime` |
| `Pagination` | 交互组件 | 上一页 / 下一页 / 页码跳转 | `current`、`total`、`pageSize`、`onChange` |
| `EmptyState` | 状态组件 | 空数据提示与插图 | `title`、`description`、`actionText` |
| `LoadingSkeleton` | 状态组件 | 列表加载骨架屏，避免布局跳动 | `count` |
| `SiteFooter` | 布局组件 | 版权与备案信息 | `copyright`、`icp`、`since` |

**交互与状态**

- **加载中**：SSR 首屏直接输出内容；客户端二次加载（翻页）显示骨架屏。
- **加载失败**：列表区展示错误提示 + 「重新加载」按钮，不影响其他区块。
- **空数据**：展示空状态文案，如「还没有发布文章，敬请期待」。
- **交互细节**：卡片 hover 时轻微上浮 + 阴影加深；整卡可点击且支持键盘 Tab 聚焦与 Enter 进入。

#### 3.1.2 验收要点

- 有文章时，首页按发布时间倒序正确展示文章，条数与分页一致。
- 草稿、已删除文章在首页不可见。
- 点击任一卡片可正确跳转到对应文章详情页（`/posts/{slug}`）。
- 375px 宽度下导航折叠为汉堡菜单，卡片单列展示，无横向滚动条。

### 3.2 F2 用户端 · 文章详情页

#### 3.2.1 功能描述

承载单篇文章的完整阅读，是产品最核心的消费场景。要求排版舒适、可读性强、阅读过程中干扰最小。

**功能点清单**

| 编号 | 功能点 | 描述 | 优先级 |
| --- | --- | --- | --- |
| F2-1 | 文章头部信息 | 标题、发布时间、更新时间（可选）、阅读时长 | P0 |
| F2-2 | 正文渲染 | 完整渲染 Markdown：标题、段落、列表、引用、代码块、表格、图片、链接 | P0 |
| F2-3 | 代码块增强 | 语法高亮 + 一键复制按钮 | P1 |
| F2-4 | 图片展示 | 图片自适应容器宽度，支持点击放大查看 | P1 |
| F2-5 | 文章目录（TOC） | 根据正文标题层级自动生成，点击锚点滚动定位 | P1 |
| F2-6 | 阅读进度 | 顶部进度条或目录高亮，反映当前阅读位置 | P2 |
| F2-7 | 上一篇 / 下一篇 | 按发布时间相邻推荐，边界情况隐藏对应入口 | P1 |
| F2-8 | 返回列表 | 提供返回首页 / 文章列表的入口 | P0 |
| F2-9 | 分享 | 复制当前页面链接 | P2 |
| F2-10 | 异常页 | 文章不存在 / 未发布 / 已删除时展示 404 提示与返回入口 | P0 |

**业务规则**

1. 仅 `status = published` 且未删除的文章可被访问；其余情况一律返回 **HTTP 404 状态码** 并渲染 404 页面，不泄露内容是否存在。
2. 阅读时长按正文纯文本字数 / 300 字每分钟估算，向上取整，最小 1 分钟。字数统计规则：中文按字符计、英文按单词计、代码块计入、Markdown 标记不计入。
3. 目录仅在有 2 个及以上二级标题时展示；桌面端右侧固定，移动端收纳为抽屉或隐藏。
4. 正文中的外链在新窗口打开并带 `rel="noopener noreferrer"`，站内链接当前页跳转。
5. 「更新时间」晚于「发布时间」超过 1 天时展示更新时间。
6. 页面 SEO：`<title>` 为「文章标题 - 站点名称」，包含 `description`（取摘要）、`og:` 系列标签、`canonical` 指向 `/posts/{slug}`。
7. 每次成功渲染详情页时上报一次阅读（计数规则见 3.8）。

**页面组件**

| 组件名 | 类型 | 说明 | 关键属性 / 状态 |
| --- | --- | --- | --- |
| `SiteHeader` | 布局组件 | 复用首页导航 | 同上 |
| `ArticleHeader` | 展示组件 | 标题 + 元信息 | `title`、`publishedAt`、`updatedAt`、`readingTime` |
| `MarkdownRenderer` | 渲染组件 | 将 Markdown 渲染为带样式的 HTML，统一处理代码、图片、表格、链接 | `content`、`headingAnchor`、`externalLinkTarget` |
| `CodeBlock` | 渲染组件 | 代码块容器，语法高亮 + 复制按钮 + 语言标识 | `code`、`language`、`copied` |
| `ImageFigure` | 渲染组件 | 正文图片，支持点击放大与图注 | `src`、`alt`、`caption` |
| `TocSidebar` | 导航组件 | 文章目录，滚动时高亮当前小节 | `headings[]`、`activeId` |
| `ReadingProgress` | 反馈组件 | 顶部阅读进度条 | `progress`（0–100） |
| `ArticleNav` | 导航组件 | 上一篇 / 下一篇 | `prev`、`next` |
| `BackToList` | 交互组件 | 返回文章列表 | `href` |
| `ShareButton` | 交互组件 | 复制链接分享，带成功提示 | `url`、`copied` |
| `NotFound` | 状态组件 | 404 提示页 | `code`、`message`、`backHref` |
| `SiteFooter` | 布局组件 | 复用首页页脚 | 同上 |

**交互与状态**

- **加载中**：SSR 直接输出正文，无骨架屏；客户端路由跳转时展示文字骨架屏。
- **404**：展示提示文案「文章不存在或已被移除」+「返回首页」按钮，同时返回 HTTP 404。
- **交互细节**：目录点击平滑滚动，锚点偏移需扣除吸顶导航高度；代码复制成功后在按钮上显示「已复制」约 2 秒。

#### 3.2.2 验收要点

- 一篇含标题、列表、代码块、表格、图片的 Markdown 文章可完整、无错位地渲染。
- 访问草稿或已删除文章的 URL 时返回 HTTP 404 状态码且不展示任何正文。
- 目录点击后目标标题滚动到可视区且不被导航遮挡。
- 移动端正文左右边距 ≥ 16px，代码块可横向滚动而不撑破页面。

### 3.3 F3 用户端 · 关于我页面

#### 3.3.1 功能描述

静态信息页，用于建立访客对博主的信任与认知，是「是否值得关注」的判断依据。

### 3.4 F4 后台 · 管理员登录

#### 3.4.1 功能描述

后台唯一入口，通过账号 + 密码校验博主身份，未登录状态下禁止访问任何后台页面。

**功能点清单**

| 编号 | 功能点 | 描述 | 优先级 |
| --- | --- | --- | --- |
| F4-1 | 登录表单 | 账号、密码输入框，支持 Enter 提交 | P0 |
| F4-2 | 表单校验 | 非空校验、长度校验，错误提示定位到具体字段 | P0 |
| F4-3 | 身份校验 | 账号密码不匹配时统一提示「账号或密码错误」，不区分哪个错误 | P0 |
| F4-4 | 登录态保持 | 登录成功后写入会话凭证（HttpOnly Cookie），刷新页面无需重新登录 | P0 |
| F4-5 | 路由守卫 | 未登录访问后台页面自动跳转登录页，并记录原目标地址 | P0 |
| F4-6 | 退出登录 | 清除登录态并回到登录页 | P0 |
| F4-7 | 防暴力破解 | 同一 IP 连续失败 5 次锁定 10 分钟（本期选用锁定策略，不做图形验证码） | P1 |
| F4-8 | 密码安全 | 密码 bcrypt 加盐哈希存储，传输使用 HTTPS，输入框支持显隐切换 | P0 |

**业务规则**

1. 本期仅支持单管理员账号，无注册、无找回密码入口。账号在系统启动时读取环境变量（`ADMIN_USERNAME` / `ADMIN_PASSWORD`）自动创建；账号已存在则不做任何修改。
2. **重置密码**：修改环境变量中的密码后重启服务，系统检测到密码变更即更新哈希。这是唯一的重置路径，文档与部署说明中需写明。
3. 登录态有效期 7 天，过期后需重新登录；Cookie 设置 `HttpOnly` + `Secure` + `SameSite=Lax`。
4. 登录成功后默认跳转仪表盘；若来自被拦截的页面则跳回原地址。
5. 页面渲染层不做权限缓存的强依赖：所有后台接口无有效会话时返回 401，前端拦截 401 统一跳转登录页。这是安全边界，而非仅靠前端路由守卫。

**页面组件**

| 组件名 | 类型 | 说明 | 关键属性 / 状态 |
| --- | --- | --- | --- |
| `LoginLayout` | 布局组件 | 居中卡片式布局，含站点标识 | `siteName`、`logoUrl` |
| `LoginForm` | 表单组件 | 账号 + 密码 + 提交按钮 | `values`、`errors`、`submitting` |
| `PasswordInput` | 表单组件 | 密码框，带显隐切换 | `value`、`visible` |
| `FormField` | 基础组件 | 标签 + 输入 + 错误提示的统一容器 | `label`、`error`、`required` |
| `SubmitButton` | 基础组件 | 提交按钮，请求中显示 loading 并禁用 | `loading`、`disabled` |
| `Toast` | 反馈组件 | 登录失败 / 成功提示 | `type`、`message` |

**交互与状态**

- **校验失败**：字段下方红字提示，输入框描边变红，聚焦首个错误字段。
- **提交中**：按钮 loading、整表禁用，防止重复提交。
- **校验失败（服务端）**：表单上方或 Toast 展示统一错误文案。
- **锁定中**：提交后提示「尝试次数过多，请 10 分钟后再试」。
- **交互细节**：密码框回车直接提交；失败后清空密码框并保持账号。

#### 3.4.2 验收要点

- 正确账号密码可登录并进入仪表盘；错误时提示统一文案且不泄露账号是否存在。
- 未登录直接访问后台任意 URL 会被重定向到登录页；登录后回到原目标页。
- 刷新后台页面不掉登录态；退出登录后调用任意后台接口返回 401。
- 修改环境变量中的密码并重启后，旧密码失效、新密码可登录。

### 3.5 F5 后台 · 仪表盘（文章统计）

#### 3.5.1 功能描述

登录后的默认落地页，用少量关键指标让博主快速掌握内容概况与阅读效果，并提供进入文章管理的高频入口。

**功能点清单**

| 编号 | 功能点 | 描述 | 优先级 |
| --- | --- | --- | --- |
| F5-1 | 文章指标卡 | 文章总数、已发布数、草稿数、本月新增数 | P1 |
| F5-2 | 阅读量指标 | 全站累计阅读量、单篇平均阅读量 | P1 |
| F5-3 | 状态分布 | 以环形图 / 进度条展示已发布与草稿占比 | P2 |
| F5-4 | 最近文章 | 展示最近更新的 5 篇文章（标题、状态、阅读量、更新时间），可点击进入编辑 | P1 |
| F5-5 | 快捷入口 | 「写新文章」「进入文章管理」「回收站」按钮 | P1 |
| F5-6 | 数据时效 | 展示统计更新时间，支持手动刷新 | P2 |
| F5-7 | 空状态 | 无任何文章时引导创建第一篇 | P1 |

**业务规则**

1. 统计口径：
   - 文章总数 = 未删除文章数（含草稿）。
   - 已发布数 / 草稿数 = 按 `status` 分组统计，排除已删除。
   - 本月新增 = `created_at` 落在当前自然月且未删除的文章数；**草稿转发布不计入**（防止同篇文章被重复计数）。
   - 累计阅读量 = 全部未删除文章 `views` 之和；平均阅读量 = 累计 / 已发布数（已发布数为 0 时显示 —）。
2. 所有数字为实时查询结果，不做长时间缓存。
3. 「最近文章」按 `updated_at` 倒序取前 5 条；点击跳转编辑页。
4. 回收站中的文章不计入任何指标，但在快捷入口上显示回收站内的数量角标。

- 各指标数值与文章管理列表中的实际数据一致（含排除回收站内文章）。

- 累计阅读量与文章列表中各篇阅读量之和相等。

### 3.6 F6 后台 · 文章管理

#### 3.6.1 功能描述

后台的核心模块，覆盖文章的「查、增、改、删、预览」全生命周期，是博主日常使用频率最高的界面。

**功能点清单**

| 编号 | 功能点 | 描述 | 优先级 |
| --- | --- | --- | --- |
| F6-1 | 文章列表 | 表格式展示全部未删除文章，分页 | P0 |
| F6-2 | 列表字段 | 标题、状态、阅读量、创建时间、更新时间、操作列 | P0 |
| F6-3 | 查询筛选 | 关键词搜索（标题 / 摘要）、状态筛选、排序，条件写入 URL 参数 | P0 |
| F6-4 | 新增文章 | 打开编辑页，填写标题、URL 标识、摘要、正文、封面、状态 | P0 |
| F6-5 | 编辑文章 | 回填已有内容并支持修改保存 | P0 |
| F6-6 | 删除文章 | 二次确认后移入回收站，成功提示并刷新列表 | P0 |
| F6-7 | 状态切换 | 在列表或编辑页切换「已发布 / 草稿」 | P0 |
| F6-8 | 批量操作 | 批量移入回收站 / 批量发布 | P2 |
| F6-9 | 保存反馈 | 保存中禁用按钮，成功后提示并留在当前页（便于连续修改） | P0 |
| F6-10 | 离开确认 | 编辑内容未保存时离开页面需二次确认 | P1 |
| F6-11 | 预览 | 打开与用户端样式一致的预览页，链接带临时 token，草稿也可查看 | P0 |

**业务规则**

1. **标题**：必填，2–100 字符；允许重名，但保存时若存在同名未删除文章需提示确认。
2. **URL 标识（slug）**：
   - 新增时由标题自动生成：中文转拼音、空格转连字符、去特殊字符、转小写。
   - 支持手动修改，仅允许小写字母、数字、连字符，长度 1–80。
   - **生成后不随标题变化**，改标题不影响链接；唯一性冲突时自动追加 `-2`、`-3` 等后缀。
   - 已发布文章的 slug 修改后，旧链接立即 404（本期不做 301 重定向，需在编辑页明确提示该后果）。
3. **正文**：必填，Markdown 格式，去除空白后为空不允许保存。
4. **摘要**：选填，≤ 200 字；为空时按 F1 规则 3 自动生成（取 120 字，句末标点截断）。
5. **状态**：仅「草稿（`draft`）」「已发布（`published`）」两种，无第三种状态。所谓「下线」= 把已发布文章改回草稿，此时用户端立即 404。
6. **发布时间 `published_at`**：首次从草稿变为已发布时写入当前时间；之后再改回草稿、再次发布**都不重置**，保持原值，因此文章在首页的位置不会因编辑而变动。
7. **删除**：采用软删除（`deleted_at`），文章从列表与用户端消失，但可在回收站恢复。删除后关联链接立即 404（见 3.7）。
8. **列表默认排序**：`updated_at` 倒序；支持按创建时间 / 更新时间 / 阅读量切换升降序。
9. **搜索规则**：关键词对标题与摘要做模糊匹配（`LIKE`，无需分词，中英文均适用），输入防抖 300ms。
10. **分页**：默认每页 10 条，可切换 20 / 50；筛选条件变化时页码重置为 1。
11. **状态同步**：所有筛选、排序、分页条件必须写入 URL query，刷新或分享链接后可复现同一视图。
12. **时间展示**：统一格式 `YYYY-MM-DD HH:mm`，与服务端时区一致（默认 Asia/Shanghai）。
13. **预览**：见 3.6.3。

- 删除文章二次确认后，列表不再出现该文章，用户端访问原链接返回 404；在回收站中可见。
- 关键词搜索与状态筛选可组合生效，结果准确；清空后可恢复全量列表。
- 分页、排序、筛选条件在刷新页面或直接粘贴 URL 后可完全复现。
- 草稿文章点击「预览」可在新标签打开，内容与发布后一致。

#### 3.6.3 预览机制

| 项 | 规则 |
| --- | --- |
| 入口 | 列表行操作「预览」、编辑页「预览」按钮 |
| 链接形态 | `/preview/{slug}?t={token}` |
| 渲染 | 复用用户端的 `ArticleHeader` + `MarkdownRenderer`，样式与详情页一致 |
| 鉴权 | token 由服务端按文章签发，有效期 2 小时，与当前登录会话绑定；失效后提示「预览链接已过期，请重新预览」 |
| 索引 | 页面对所有爬虫返回 `noindex, nofollow`，且不出现在 sitemap 中 |
| 范围 | 仅可预览草稿；已发布文章的预览直接跳转正式详情页 |

### 3.7 F7 后台 · 文章回收站

#### 3.7.1 功能描述

承接文章软删除的恢复能力，避免误删造成不可逆的内容损失。

**功能点清单**

| 编号 | 功能点 | 描述 | 优先级 |
| --- | --- | --- | --- |
| F7-1 | 回收站列表 | 展示已删除文章：标题、删除前状态、删除时间、阅读量 | P1 |
| F7-2 | 恢复文章 | 恢复后回到删除前状态（草稿或已发布），回到文章列表 | P1 |
| F7-3 | 彻底删除 | 二次确认后物理删除，不可恢复，需输入标题确认（防误操作） | P1 |
| F7-4 | 自动清理 | 超过 30 天的已删除文章由定时任务物理清除 | P2 |
| F7-5 | 空状态 | 回收站为空时展示「回收站是空的」 | P1 |

**业务规则**

1. 回收站内文章不参与任何统计（仪表盘指标、首页列表、上一篇/下一篇）。
2. 恢复已发布文章时，若原 slug 已被其他文章占用，自动追加后缀并提示。
3. 恢复后 `published_at` 保持原值，文章回到首页原位置。
4. 彻底删除为不可逆操作，需输入文章标题后按钮才可点击。

**页面组件**

| 组件名 | 类型 | 说明 | 关键属性 / 状态 |
| --- | --- | --- | --- |
| `AdminShell` / `SideNav` | 布局组件 | 复用后台外壳，回收站为独立菜单项 | 同上 |
| `TrashTable` | 数据组件 | 回收站表格 | `rows[]`、`loading` |
| `RestoreButton` | 交互组件 | 恢复操作，带二次确认 | `id`、`onRestore` |
| `DangerConfirmDialog` | 弹窗组件 | 彻底删除确认，需输入标题 | `open`、`expectedTitle`、`onConfirm` |
| `EmptyState` | 状态组件 | 回收站为空提示 | 同上 |

**交互与状态**

- **恢复成功**：Toast 提示并刷新回收站列表，文章数量角标同步减少。
- **彻底删除**：输入标题匹配后才启用确认按钮，删除后不可恢复。

#### 3.7.2 验收要点

- 删除文章后可在回收站看到，恢复后回到文章列表且状态与删除前一致。
- 恢复后的文章在用户端可正常访问（slug 未冲突时链接不变）。
- 彻底删除后数据不可恢复，文章数量与阅读量统计同步减少。

### 3.8 关键数据字段与计数规则

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | 主键 | 自增 / UUID，仅内部使用，不出现在 URL |
| `title` | 字符串 | 必填，2–100 字符 |
| `slug` | 字符串 | 必填，唯一，生成后固定；`/posts/{slug}` |
| `summary` | 字符串 | 选填，≤200 字；空时自动生成 120 字 |
| `content` | 文本 | Markdown 原文，必填 |
| `cover_url` | 字符串 | 选填；本期仅支持单图上传，格式 jpg/png/webp，≤5MB |
| `status` | 枚举 | `draft` / `published`，仅两种 |
| `published_at` | 时间 | 首次发布写入，此后不重置 |
| `created_at` | 时间 | 创建即写入 |
| `updated_at` | 时间 | 每次保存刷新 |
| `deleted_at` | 时间 | 软删除标记，非空即视为已删除 |
| `views` | 整数 | 累计阅读量，默认 0 |

**阅读量计数规则**

1. 统计发生在服务端渲染详情页时（或由前端调用一次上报接口），**同一 IP + 同一文章 30 分钟内只计 1 次**，防刷新刷量。
2. 计数写入失败不影响页面渲染（异步、可丢弃）。
3. 回收站内文章不再计数；恢复后沿用原 `views`。
4. 累计阅读量只增不减，除彻底删除外不重置。

| 规则 | 说明 |
| --- | --- |
| 公开可访问 | 用户端三个页面、已发布文章数据、站点基础配置 |

## 4. 非功能性需求

### 4.1 响应式设计

#### 4.1.1 目标

一套代码适配桌面、平板、手机三类终端，保证任何常见视口下内容完整可读、可操作，无横向滚动条与元素重叠。

#### 4.1.2 断点定义

| 断点 | 视口宽度 | 代表设备 | 布局策略 |
| --- | --- | --- | --- |
| Mobile | < 768px | 手机（竖屏） | 单列布局，导航折叠为汉堡菜单，字号与点击区放大 |
| Tablet | 768px – 1023px | 平板（竖屏）/ 小笔记本 | 两列或窄栏单列，导航可完整展示 |
| Desktop | ≥ 1024px | 桌面 / 笔记本 | 内容区定宽居中（最大 1200px），支持侧栏与目录 |
| Wide | ≥ 1440px | 大屏 | 内容区保持定宽，两侧留白，不无限拉伸 |

#### 4.1.3 各页面响应式要求

| 页面 | 移动端（< 768px） | 平板（768–1023px） | 桌面（≥ 1024px） |
| --- | --- | --- | --- |
| 首页 | 导航折叠为汉堡菜单；Hero 头像与文字上下堆叠居中；文章卡片单列全宽 | 卡片两列；Hero 横向排列 | 卡片两到三列网格；Hero 左文右图，内容区居中 |
| 文章详情 | 正文单列，左右内边距 16px；目录隐藏或收纳为浮动抽屉；代码块横向滚动；图片宽度 100% | 正文单列加宽，目录可折叠展示在正文上方 | 正文 720–800px 定宽 + 右侧吸附目录，左侧留白 |
| 关于我 | 各模块纵向堆叠，头像居中 | 双列：左资料卡固定，右内容滚动 | 双列布局，资料卡吸附 |
| 登录页 | 卡片占满宽度（留 24px 边距），垂直居中 | 定宽 400px 居中卡片 | 定宽 400px 居中卡片，可加侧边品牌区 |
| 后台仪表盘 | 侧边栏收为抽屉；指标卡单列或两列；图表全宽 | 指标卡两列；侧边栏折叠为图标 | 侧边栏常驻 240px；指标卡四列；图表与最近文章并排 |
| 文章管理列表 | 表格改为卡片列表（标题 + 状态 + 阅读量 + 时间 + 操作），避免横向滚动 | 保留表格，隐藏次要列（如创建时间） | 完整表格展示全部字段 |
| 文章编辑页 | 表单上下堆叠，属性区置于正文下方；编辑器全屏可用 | 上下堆叠，正文编辑区加高 | 双栏：左正文、右属性栏 |
| 回收站 | 卡片列表，操作按钮常驻 | 表格，隐藏阅读量列 | 完整表格 |

#### 4.1.4 通用适配规则

1. **栅格与弹性**：使用弹性布局 / CSS Grid 实现，禁止固定像素宽度导致溢出；容器宽度用百分比与 `max-width` 组合。
2. **触控友好**：移动端所有可点击元素热区 ≥ 44×44px，相邻可点击元素间距 ≥ 8px。
3. **字号与行高**：正文移动端 ≥ 16px、桌面端 16–18px，行高 1.6–1.8；标题按视口使用 `clamp()` 平滑缩放。
4. **图片与媒体**：图片 `max-width: 100%`、`height: auto`，使用 `srcset` / 懒加载；视频与 iframe 按 16:9 自适应容器。
5. **表格与代码**：宽表格与代码块容器内横向滚动，不撑破页面布局。
6. **视口与安全区**：声明 `viewport` meta；适配刘海屏 `env(safe-area-inset-*)`。
7. **导航形态**：移动端优先汉堡菜单 + 抽屉，抽屉打开时锁定背景滚动，点击遮罩或 ESC 关闭。
8. **横竖屏**：横屏时保证内容不被裁切，允许自然滚动。
9. **主题与对比度**：文字与背景对比度 ≥ 4.5:1，支持系统深色模式（P2）。

#### 4.1.5 验收标准

- 在 375px、768px、1024px、1440px 四个典型宽度下，全部页面无横向滚动条、无元素重叠、无文字截断。
- 移动端导航菜单可正常展开、关闭，且不遮挡关键操作。
- 后台文章管理在 375px 下不出现横向滚动即可完成增删改查与预览。
- 使用浏览器设备模拟与真机各验证一次，表现一致。

### 4.2 性能要求

| 指标 | 目标 |
| --- | --- |
| 首页首屏渲染（4G 网络） | ≤ 2s |
| 文章详情页首屏 | ≤ 2s，正文可读时间 ≤ 2.5s |
| 后台列表与保存操作响应 | ≤ 1s（不含网络异常） |
| 图片 | 懒加载 + 压缩，单图 ≤ 300KB（列表封面） |
| 交互反馈 | 任何异步操作 200ms 内给出 loading 或状态反馈 |
| 阅读量计数 | 不阻塞页面渲染，独立异步写入 |

### 4.3 兼容性要求

- 浏览器：Chrome / Edge / Safari / Firefox 最近两个大版本；移动端 iOS Safari 与 Android Chrome。
- 不要求兼容 IE。

### 4.4 安全要求

- 全站 HTTPS；后台接口鉴权，密码 bcrypt / argon2 加盐哈希存储。
- 所有用户输入做服务端校验与转义，Markdown 渲染需过滤 XSS 危险标签与属性（白名单策略）。
- 封面图上传校验：仅 jpg / png / webp，单文件 ≤ 5MB，重命名后存储，禁止可执行后缀。
- 登录失败限流（5 次 / 10 分钟）；预览 token 有时效且绑定会话。
- 后台所有写操作接口校验会话与请求来源，防 CSRF。

### 4.5 可用性与可维护性

- 用户端页面在无数据、无网络时均有明确状态提示，不出现白屏；404 返回真实 HTTP 状态码。
- 代码分层清晰（页面 / 组件 / 数据访问分离），关键配置（站点名、社交链接、关于我内容）集中管理。
- **数据备份**：数据库每日自动备份，保留最近 7 天；备份文件存储在站点目录之外。文章是本站唯一核心资产，此项为必做而非可选。
- 错误日志可追踪；后台关键操作（发布、删除、彻底删除）留痕。

### 4.6 SEO 与可访问性

- SSR 输出完整 HTML，爬虫可获取正文；语义化标签（`header` / `nav` / `main` / `article` / `footer`），每页唯一 `h1`。
- 提供 `title`、`description`、`og:` 标签、`canonical` 与 `sitemap.xml`（P1）。
- 草稿、预览页、404 页返回 `noindex`。
- 图片必须有 `alt`；表单控件关联 `label`；键盘可完成主要操作路径；焦点样式可见。
