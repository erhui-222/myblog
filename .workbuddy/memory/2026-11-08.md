### 技术方案（同日晚）

产出 `memory-bank/TECH_DESIGN.md`，与 PRD 配套。核心选型：

- Next.js 15 App Router + React 19 + TypeScript + Tailwind CSS 4
- Prisma 6 + SQLite（可迁 Postgres）；bcrypt；自建 Session 表 + HttpOnly Cookie
- unified Markdown 管线（remark-gfm / rehype-slug / rehype-pretty-code+shiki / rehype-sanitize）
- 自研 textarea + 分栏预览编辑器；纯 SVG 环形图
- Docker Compose（app standalone + Caddy）+ 单台 VPS + 卷挂载 + 每日 VACUUM INTO 备份

关键架构决策（写代码时必须遵守）：

1. 分层：app/ 不写 Prisma，全部走 lib/services/；service 不收 Request
2. middleware.ts 跑 Edge 连不上 DB，只做 cookie 粗筛；真正鉴权在 admin/layout.tsx 与每个 API
3. 写操作走 Route Handler 而非 Server Actions（PRD 要求 401 语义）
4. 详情页动态 SSR（阅读量按请求计数）；关于我 revalidate 3600
5. 后台路由用 id，前台用 slug

踩坑记录（数据库）：

- SQLite 不支持 enum → status 用 String + zod 约束
- SQLite 不支持 Prisma 的 `mode: 'insensitive'` → 直接 contains
- 阅读去重用 `bucket = floor(now/30min)` + `@@unique([postId, ipHash, bucket])`，插入冲突即重复访问
- 备份必须 `VACUUM INTO`，不能直接 cp（WAL 下快照不一致）

里程碑：M0 骨架/数据层 → M1 用户端只读 → M2 认证+后台读写 → M3 统计+回收站 → M4 打磨上线。原则是先「读」后「写」。

7. 删除 → 前台 404 → 回收站可见 → 恢复 → 前台 200
